Why this matters

MCP is the plug that lets AI agents use real software

The Model Context Protocol gives an AI agent a structured list of tools it can call — no screen-scraping, no guesswork. Instead of describing what to click, the agent calls screenshot, reads the result, and calls mouse with exact coordinates. RemotePC's MCP endpoint turns that same idea into remote control: one connection, any number of your configured host computers, every action a real, well-defined tool call.

One endpoint, every host

A single MCP URL on your account reaches every computer you've already set up with RemotePC — no per-machine integration.

Same access, now governed

The agent only gets what the signed-in user already allows — locked desktops, opt-in command execution, and opt-in restart are all enforced on the host.

Built for agent workflows

Structured JSON in, structured JSON out. Your agent can chain screenshot → click → verify without parsing pixels or guessing menu paths.

Sign in when prompted

The first tool call opens a RemotePC login page in your browser. Sign in with your normal RemotePC account — the same one that already manages your host computers.

Choose permission & duration

Pick read-only (look, don't touch) or read-write (full control), and how long the grant should last — from a few minutes up to 30 days. Confirming re-prompts sign-in once more to finalize the grant.

Security by design

The agent only gets what the host already allows

MCP access rides on the same trust model RemotePC already enforces locally — nothing new to configure, nothing silently unlocked.

Locked-desktop protection

Screen capture, mouse, keyboard, and window listing all refuse to run on a locked, screen-saver, or secure desktop.

Opt-in for the risky ones

Command execution, restart, and software update are off until the person at that computer turns them on locally — no remote override.

No file or image bytes in chat

Screenshots and file reads always return a short-lived signed URL — never inline base64 — so large payloads never sit in agent context or logs.

One action at a time

Each host runs a single tool call at a time; an overlapping call gets a clear "busy, retry" response instead of racing input.

Read-only or read-write, your choice

Grant observation-only access for monitoring, or full control when the agent needs to act — chosen per session, not a fixed, all-or-nothing scope.

Access expires on its own

Every grant has a time limit you set up front — from 12 hours to 30 days. No lingering access to clean up later.

FAQ

Good to know

Do I need to install anything besides RemotePC?

No. The MCP server is hosted by RemotePC — your agent connects to one HTTPS endpoint. The host computer only needs its regular RemotePC agent running and online.

Which AI agents can I use?

Any MCP client that supports a remote (Streamable HTTP) MCP server — including Claude Desktop, Cursor, and custom agents you build yourself.

Can the agent reach a computer that isn't set up with RemotePC yet?

No. The agent can only reach hosts already configured and online on your RemotePC account — MCP access doesn't add new machines, it adds a new way to control the ones you've already set up.

What stops an agent from running a dangerous command?

Command execution, restart, and software update all stay disabled until the person at that specific computer opts in locally. Everything else still requires an unlocked, interactive session.

What's the difference between read-only and read-write?

Read-only limits the session to observation tools — screenshots and the window list. Read-write unlocks everything: mouse, keyboard, commands, files, chat, restart, and update.

What happens when my session expires?

Tool calls start returning an authorization error. Reopen your MCP client and repeat the sign-in and permission step to renew — there's no automatic silent renewal.

Can I end a session early?

Yes. Revoke it from your RemotePC account at any time; it takes effect immediately, even in the middle of a conversation with the agent.

Do I have to repeat sign-in for every host I control?

No. One sign-in and permission grant covers every host already configured on your account for the duration you chose — you don't re-authenticate per machine.
